## 4. System One 的用詞

**問題**：投影片原本標「規則＝System 1、Gemini 選擇題＝System 2」。

**參考**：[System One 模型與 Jev](https://warmwater.dev/blog/system-one-jev-workflow/)（2026-10-12）。TypeSafe 在 9 月推出 Jev，稱為「System One 模型」：只做判斷，讀進狀態、回答事先定義好的問題，一次回傳固定格式的答案和機率；有把握就交給程式，沒把握才升級給更強的模型或人。名稱來自《快思慢想》的系統一。文章沒有定義 System 2。

**行動**：照這個定義，「讓 LLM 做選擇題」本身就是 System One，和 11/4 學長的建議一致。投影片改成「LLM 只做選擇題／System One」「Gemini 選擇題／System One 判斷」，拿掉 System 2；在第 12 頁（選擇題第一次出現的地方）介紹，第 13 頁只回頭指。`design/llm-design.md` 加一段用詞更正，11/5 的原始整理保留。

**要講清楚的差別**：OneRide 沒有用 Jev，是用 Gemini 照這個概念做；Jev 會回傳機率，Gemini 不會，所以「有沒有把握」由規則那一層判斷。換成 System One 類模型可以當之後的改進。

## 最重要的發現

**一致性要從架構保證，測試只是確認沒漏掉。** 前端「同一個輸入、同一種結果」是因為所有入口收斂到同一個查詢函式、同一支 API、同一份結構化資料；8 條原則和入口 × 操作表是用來檢查的。後端也是同樣的道理：LLM 只做選擇題、回答由程式產生，答案就不會因為 LLM 而變。

## 學到的觀念

- **反向代理（reverse proxy）**：站在伺服器這一側替後端收請求（nginx、Vite proxy、Tailscale serve 都是）；正向代理站在使用者那一側替使用者出去（例如學校的上網代理）。
- **同源政策**：瀏覽器只讓網頁讀同一個來源（協定、網域、埠號都一樣）的回應，防止別的網站用你的登入身分讀資料。nginx 把網頁和 /api 放在同一個網址，就不用設 CORS，api 和資料庫也不用對外開放；代價是多一層設定（nginx 預設等 60 秒，曾造成 504）。
- **前端在哪裡**：Vue 程式打包後存在 nginx，手機打開網頁時送過去，在手機的瀏覽器裡執行。
- **講稿裡的數字要回頭查原始紀錄**：同一段話混了兩件事，只有對照驗收紀錄才看得出來。
- **投影片格式的限制**：這套投影片會忽略文字框的高度和垂直置中，方塊要用 SVG 畫，或用內距撐高，箭頭才接得上。
