## 1. 前端技術選擇：Leaflet + OpenStreetMap

**問題**：網頁地圖的工具很多，要選一個適合這個專案的。

**參考**：Google Maps JS API、Mapbox GL JS、MapLibre GL JS、OpenLayers、Leaflet 的官方文件與授權條款。

**行動**：先分清楚兩件事：**地圖函式庫**負責在網頁上顯示與互動，**底圖**是圖磚資料，兩者可以分開換。

| 選項 | 費用／金鑰 | 特點 |
| --- | --- | --- |
| Leaflet + OSM | 免費、不用金鑰 | 輕量、API 簡單 |
| Google Maps JS API | 要 API key 並綁信用卡 | 資料最完整，條款限制多 |
| Mapbox GL JS | 要 token | 向量圖磚，非開源授權 |
| MapLibre GL JS | 開源 | 要自己找向量圖磚來源 |
| OpenLayers | 開源 | 功能完整，學習曲線陡 |

**結果**：選 Leaflet + OSM。

- **不用金鑰**：前端程式碼會整包送到瀏覽器，key 藏不住。
- **需求簡單**：只需要底圖、點擊取座標、標記、popup。
- **時程短**：核心概念少。

限制：OSM 官方圖磚只適合開發和小流量，必須標示「© OpenStreetMap contributors」。正式上線要換圖磚來源，只需要改一行網址。

## 2. 點地圖查詢可直達的下車站

**問題**：前端在 port 5173，後端在 port 8000，瀏覽器會擋下不同來源的請求。

**參考**：Vite 的 `server.proxy` 設定、Leaflet 的 `circleMarker`、`bindPopup`、`L.canvas`。

**行動**：

- Vite proxy：前端一律呼叫 `/api/reach`，由 Vite 去掉 `/api` 再轉給後端。後端不用另外開 CORS，之後 Docker 也可以沿用 `/api` 這個路徑。
- 點地圖 → 紅點標出起點 → 呼叫 API → 每個下車站畫一個藍點；再點一次就清掉舊結果。
- 點藍點跳出 popup，列出路線、去程或返程、上車站與距離、站數。
- 藍點改用 Canvas 繪製，設定點擊容許範圍 8 px，否則半徑幾 px 的圓點很難點中。

**結果**：

| 驗證項目 | 結果 |
| --- | --- |
| 測試起點（興隆路二段 218 號） | 375 個下車站，和後端一致 |
| 銘傳大學 | 109（27 站）、606、606通勤（30 站），都是去程、興隆國小上車 |
| 點台北市外（桃園） | 後端回 422，畫面顯示查詢失敗 |

縮小地圖後，藍點從興隆路一路延伸到士林、陽明山，可以直接看出路線的走向。

## 3. 附近上車站：後端加上 `boarding` 清單

**參考**：`04_nearby.sql`（300 m 內的站牌）、`07_direct_reach.sql`（JOIN 與距離）。

**行動**：決定在 `/reach` 的回傳加上 `boarding` 清單，不另外開一支 API，因為前端只要呼叫一次。

## 最重要的發現：同一個站，資料來源之間有落差

**1. 同一個 `station_id` 底下，各路線的站牌座標不一定相同**

全部 5,375 個站位中，有 237 個站位底下的 `stop_uid` 座標不一樣，最遠相差約 100 m（用度數粗估）。所以同一次查詢裡會有兩種距離：

- 附近站牌的距離：站位裡最近的那一點。
- popup 裡的上車距離：這條路線自己的站牌。

這兩個數字可能不同。兩者都正確，只是意思不一樣。測試起點附近的 11 個站位剛好完全一致。

**2. TDX 和 OSM 底圖的站牌位置差十幾到幾十公尺**

橘點來自 TDX，OSM 底圖上的公車站圖示是志工標的，兩邊各自量測，所以位置會有落差。這不是程式錯誤：如果經緯度寫反，點會跑到幾千公里外。哪一邊比較準，要到現場確認才知道。路線資料一律以資料庫為準。

**3. 有些站同時是上車站和下車站**

例如福興路口（194 m）：可以在這裡上車，也可以從興隆國小坐 1 站到這裡。這種「走路比較快」的結果要不要過濾，還沒決定。

## 學到的觀念

**同源政策與 proxy**

來源由協定、主機、port 三者決定，只要 port 不同就算不同來源。瀏覽器不讓網頁的 JavaScript 讀取其他來源的回應，但這個限制**只存在於瀏覽器**，伺服器之間的請求不受影響。所以由 Vite（伺服器）代為轉送就可以繞過。

**經緯度順序：只靠位置的地方最危險**

| 寫法 | 順序 | 誰規定的 |
| --- | --- | --- |
| Leaflet `[lat, lng]` | 緯度在前 | Leaflet |
| PostGIS `ST_MakePoint(lng, lat)` | 經度在前（x, y） | PostGIS |
| API `?lng=&lat=` | 不影響 | 參數有名稱 |

**不會報錯的錯誤**

| 寫法 | 後果 |
| --- | --- |
| `direction === '0'`（數字和字串比較） | 永遠是 false，所有路線都顯示返程 |
| 點下車站時，click 繼續傳給地圖（Leaflet 預設） | 地圖重新查詢，popup 被清掉 |
| `GROUP BY` 加入 `geom` 來避開聚合錯誤 | 同一站位被拆成多列 |

**`GROUP BY` 的規則**：`SELECT` 裡的欄位，要嘛寫在 `GROUP BY`，要嘛被聚合函式包起來。要留下「最近的距離」就用 `MIN`，而不是把 `geom` 加進分組。
